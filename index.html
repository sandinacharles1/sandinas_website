Sandinify: Music Uploading, Listening, and DSP Editor Platform

Started: Sep 2026   Status: In progress   Code

A full-stack music platform for uploading, listening to, and editing tracks with built-in DSP tools (in progress). The backend core is built and load-tested: authentication, rate limiting, tracing, a containerized setup, and cloud song storage on AWS S3.

  • Sustained a 1,000 req/s k6 load test while rejecting 99.8% of over-limit requests (HTTP 429), protecting the API from brute-force attacks and request flooding, by building a Redis-backed token-bucket rate limiter as a Spring Boot filter with an atomic Lua script.
  • Held p95 latency below 12 ms under load by tracing API endpoints, token verification, and SQL queries with OpenTelemetry and Jaeger.
  • Secured user accounts with Argon2id password hashing and JWT refresh tokens, backed by 12 passing JUnit/MockMvc tests (up from 0) covering signup, login, token refresh, and invalid credentials, on Spring Data JPA and PostgreSQL.
  • Enabled immediate invalidation of compromised sessions and secure logout, with sub-2 ms checks, by pairing 15-minute JWT access tokens with a Redis token-revocation blacklist.
  • Cut local setup from 6 manual steps to 1 command (docker compose up) by containerizing the API, PostgreSQL, Redis, and Jaeger with Docker Compose.
  • Designed an asynchronous upload pipeline (S3, PostgreSQL, Redis queue) that queues each song for audio feature analysis (genre, mood, tags), returning 201 immediately and using the database as the source of truth so duplicate or lost jobs can’t corrupt state.
Java · Spring Boot · React.js · PostgreSQL · Redis · Docker
